# XR30 下一版待办

## eMMC 剩余空间自动初始化

登记日期：2026-09-29。状态：待实现、待实机验证；当前固件尚无此功能。

目标：XR30 / RAX3000Z 增强版的 DDR4/eMMC 设备刷入下一版固件后，
自动将可用的剩余空间作为通用数据盘，挂载到 `/mnt/data`，用于备份和文件。
应用功能继续通过独立部署脚本安装，不因本项预装文件共享或容器服务。

### 实现范围

- [ ] 从设备读取实际容量与 GPT，严格识别受支持的 eMMC 启动和分区布局；
  不仅凭沿用的 `cmcc,rax3000m` compatible 判断设备适用性，不对 NAND 执行本逻辑。
- [ ] 在主 GPT 有效、既有分区完整且空闲范围确认后，修正容量记录，
  在真实磁盘末尾重建备份 GPT，使用剩余可用空间创建 `data` 分区。
- [ ] 保留现有分区的编号、位置、类型、名称、GUID 和属性，包括
  `ubootenv`、`factory`、`fip`、`recovery`、`production` 及保留分区。
  保留磁盘 GUID；不重刷 U-Boot，不重建整盘分区表，不扩容系统 overlay。
- [ ] 仅格式化本次初始化流程新建且明确可初始化的数据分区，使用 ext4；
  已有文件系统只识别和挂载，未知布局或状态停止操作并给出诊断。
- [ ] 按文件系统 UUID 挂载到 `/mnt/data`，提供 `backups/`、`firmware/`
  和 `files/` 目录。挂载失败时不允许数据写入任务误写到系统 overlay。
- [ ] 预置必要的分区、ext4 和挂载支持，保持官方内核 ABI 与软件源兼容，
  继续通过现有构建校验；不覆盖其他用户定义的挂载配置。
- [ ] 初始化可重复执行并可从中断中恢复。不能仅凭系统内的完成标记决定是否格式化；
  分区已创建但格式化未完成等中间状态必须有明确的恢复策略。
- [ ] 支持首次安装、保留配置升级和不保留配置升级：已有数据盘均应保留并恢复挂载。
  该保证限于经过验证的正常 FIT sysupgrade 路径，不涵盖整盘镜像或 GPT 重刷。
- [ ] 新分区若不能在线被内核识别，定义受控的重启与续接流程，避免循环重启。

### 验收要求

- [ ] 用磁盘镜像测试正常布局、容量不匹配、无效备份 GPT、未知分区、
  已有文件系统和中断状态，确认原有分区元数据与内容均未被覆盖。
- [ ] 实机验证首次初始化、重复启动和掉电恢复；已有文件不得被重复格式化。
- [ ] 写入测试文件并保存校验值，分别进行保留配置和不保留配置升级，
  验证自动挂载、校验值及原有网络功能。
- [ ] 先完成实机流程验证，再将自动初始化纳入下一版候选固件。
