## 蜂窝 IPv6 接口 `cellular6` 实机验收

2026-11-26 已加入固件源码并通过本地模拟回归，待逐棒实测。机主已确认 ML307R、UFI001C、UFI003C
支持 IPv6。每种棒及所用 APN 能否向 XR30 提供公网连通性和可下发的前缀，需分别记录。

- [ ] 在实机确认全新安装创建 `cellular6`，使用 `proto dhcpv6`，与 `cellular` 并列绑定到同一个
  由固件识别的数据设备。复用现有 USB 匹配及命名，干净安装用 `cell0`，旧版可能是
  `ml307r0`。由 netifd 管理热插拔及冷启动。允许 SLAAC，尝试申请地址和任意可用长度的
  PD（`reqaddress=try`、`reqprefix=auto`）。两种协议独立运行，IPv6 失败不重启 IPv4。
- [ ] 单独执行 IPv6 升级检查。关联 UCI 配置、动态接口的生成者和 ubus 的实际设备；
  同一承载已有等效客户端时复用原名。PSG 优先读取标准名，旧配置通过接口枚举，以协议类型、
  与蜂窝相同的 `l3_device` 及其配置归属解析实际逻辑名；无法唯一匹配时报告未知。保留手动停用、
  DNS、选路和防火墙设置。遇到同名冲突、自定义策略歧义或离线时无法排除重复，记录原因，
  待承载可识别时再判断。重复运行或重插后，每个承载最多一个 DHCPv6 客户端。
- [ ] 新接口沿用 `cellular` 所属上联区域，出厂为 `wan`。核对 DHCPv6 回复、RA、邻居发现、
  Packet Too Big 等 ICMPv6 和 LAN 向上转发；保持蜂窝侧 SSH、HTTP、HTTPS 入站限制。
  双线默认保持有线优先，检查 IPv6 路由的源前缀和优先级。主动双栈主备交由 PSG。
- [ ] 通过 `network.interface dump` 和对应接口的 `status` 提供 `l3_device`、有效地址、
  默认路由及源限制、前缀及租期。分开记录本机公网实测、DHCPv6 IA_PD、LAN 前缀分配
  和客户端公网实测。已有静态前缀或前缀扩展时，核实来源；缺少 PD 时保留 IPv4 和可用的
  本机 IPv6，不自动启用 NAT66 或中继。拔出时撤销该棒的路由与委派，核对 LAN 旧前缀弃用。
- [ ] 分别记录三款棒的型号、APN、固件提交、蜂窝设备、本机 IPv6 公网结果、PD、
  有线与 Wi-Fi 客户端实际出口。每款覆盖有线 WAN 同时在线、拔插一次和插棒重启一次；
  加测 IPv4-only、IPv6 无 PD、全新与保留配置升级，包括已存在手动或动态 IPv6 接口。

实现依据见[现有蜂窝初始化](../../package/network/config/xr30-ml307r/files/defaults)、

## 无线出厂设置和手动无线上行

2026-11-24 确认。以下出厂设置适用于首次安装、恢复出厂设置和不保留配置升级。

- [x] 已在源码设置 5 GHz AP 默认开启，沿用当前默认 SSID，采用 WPA2-PSK（AES/CCMP）
  和机主指定的公开出厂口令。AP 接入 `lan`，与物理 LAN 口共享 `br-lan`。出厂国家码
  为 `CN`，主信道 36，带宽 80 MHz。在日本或美国使用时手动设置 `JP` 或 `US`。
- [x] 2.4 GHz 在该机上为 `radio0`，已在源码设为出厂关闭。根据实际频段匹配无线设备。
  出厂配置不创建无线客户端、`wwan` 接口、热点凭据或自动切换规则。
- [ ] 干净刷机后，用手机连接 5 GHz，验证 DHCP、HTTPS 管理和 LAN 设备访问，并检查
  2.4 GHz 已关闭。修改无线配置后重启和保留配置升级，验证机主设置得到保留。

### 需要连接手机热点或桌面上游 AP 时

在 LuCI 的“网络 → 无线”中使用 2.4 GHz 射频扫描并加入上游，选客户端模式，创建
`wwan`，使用 DHCP 客户端并加入已有 `wan` 防火墙区域。启用该射频及客户端，
保留其默认 AP 为禁用。上游热点与 XR30 的 LAN 应使用不同网段。

这套设置由机主在设备上按需完成。调试电脑可以通过 5 GHz 访问 LAN 口的硬件。
可分别用普通 AP 和手机热点验证上网、热点重连，以及断开上游后的本地访问。

## eMMC 剩余空间自动初始化

登记日期：2026-09-29。状态：待实现、待实机验证；当前固件尚无此功能。

目标：XR30 / RAX3000Z 增强版的 DDR4/eMMC 设备刷入下一版固件后，
自动将可用的剩余空间作为通用数据盘，挂载到 `/mnt/data`，用于备份和文件。
应用功能继续通过独立部署脚本安装，不因本项预装文件共享或容器服务。

### 实现范围

- [ ] 从设备读取实际容量与 GPT，严格识别受支持的 eMMC 启动和分区布局；
  不仅凭沿用的 `cmcc,rax3000m` compatible 判断设备适用性，不对 NAND 执行本逻辑。
- [ ] 在主 GPT 有效、既有分区完整且空闲范围确认后，修正容量记录，
  在真实磁盘末尾重建备份 GPT，使用剩余可用空间创建 `data` 分区。
- [ ] 保留现有分区的编号、位置、类型、名称、GUID 和属性，包括
  `ubootenv`、`factory`、`fip`、`recovery`、`production` 及保留分区。
  保留磁盘 GUID；不重刷 U-Boot，不重建整盘分区表，不扩容系统 overlay。
- [ ] 仅格式化本次初始化流程新建且明确可初始化的数据分区，使用 ext4；
  已有文件系统只识别和挂载，未知布局或状态停止操作并给出诊断。
- [ ] 按文件系统 UUID 挂载到 `/mnt/data`，提供 `backups/`、`firmware/`
  和 `files/` 目录。挂载失败时不允许数据写入任务误写到系统 overlay。
- [ ] 预置必要的分区、ext4 和挂载支持，保持官方内核 ABI 与软件源兼容，
  继续通过现有构建校验；不覆盖其他用户定义的挂载配置。
- [ ] 初始化可重复执行并可从中断中恢复。不能仅凭系统内的完成标记决定是否格式化；
  分区已创建但格式化未完成等中间状态必须有明确的恢复策略。
- [ ] 支持首次安装、保留配置升级和不保留配置升级：已有数据盘均应保留并恢复挂载。
  该保证限于经过验证的正常 FIT sysupgrade 路径，不涵盖整盘镜像或 GPT 重刷。
- [ ] 新分区若不能在线被内核识别，定义受控的重启与续接流程，避免循环重启。

### 验收要求

- [ ] 用磁盘镜像测试正常布局、容量不匹配、无效备份 GPT、未知分区、
  已有文件系统和中断状态，确认原有分区元数据与内容均未被覆盖。
- [ ] 实机验证首次初始化、重复启动和掉电恢复；已有文件不得被重复格式化。
- [ ] 写入测试文件并保存校验值，分别进行保留配置和不保留配置升级，
  验证自动挂载、校验值及原有网络功能。
- [ ] 先完成实机流程验证，再将自动初始化纳入下一版候选固件。
